# Публикация исходников через GitHub Desktop

Используйте папку DeepSeek-Harness-CleanFix-Source. У неё самостоятельная история без прежних бинарных архивов. Точный SHA проверенного коммита передаётся в локальной памятке; в History GitHub Desktop сверяйте полный SHA.

1. File → Add Local Repository → выберите новую папку. Проверьте main и No local changes.
2. Если origin уже настроен на ваш опубликованный репозиторий исходников, самостоятельно выполните Push origin. Если remote отсутствует, используйте Publish repository под свободным именем и снимите Keep this code private. Автоматическая публикация при подготовке не выполняется.
3. Сдавайте URL конкретного коммита /commit/FULL_SHA. Ссылка на main не фиксирует проверенную версию.

Старые репозитории прежних бинарных комплектов могут содержать архивы в прошлых коммитах. Удаление payload следующим коммитом не удаляет их из истории. Не смешивайте такую историю с этой папкой исходников. Замена опубликованной истории автоматически не выполняется.

После скачивания исходников зависимости устанавливаются по инструкции. Не добавляйте node_modules, pnpm store, готовые бинарники, модели, VM, пароли, сессии и сырые логи.

Проверка файлов и всех локальных Git-объектов:

```powershell
python deploy/Verify-Publication.py --allowlist-file deploy/privacy-allowlist.json --private-values-file C:\Private\audit-values.json
```

audit-values.json — ваш приватный JSON-массив известных секретов вне репозитория; при его отсутствии опустите этот аргумент. В allowlist проверены только общая подпись автора и точный публичный origin без credentials; другой URL или другие значения не допускаются этой записью. Reflog GitHub Desktop тоже может содержать личную подпись, хотя сам reflog не передаётся push. Шаблонный скан не доказывает отсутствие любого мыслимого секрета.
