# Результаты и границы проверки

## Установка из исходников на новой Windows 11

16 октября 2026 года проверен код коммита `605a34c61f8f494df9c06c5fb00aa1f46764daab` в заново установленной Windows 11 Pro x64 26300.9457. Обезличенные результаты: [clean-source-vm.json](evidence/clean-source-vm.json). Проверка выполнялась под обычным DSHAudit, без включения в Administrators.

Исходники перенесены точным Git bundle: прямой доступ к github.com:443 в этой сети не работал. Git проверил bundle и commit/tree опубликованной базы. Проверку TLS не отключали. Инструменты и модель установлены отдельно; node_modules, pnpm store и готовую сборку с хоста не переносили. Зависимости установлены заново из registry по frozen lockfile с package-import-method=copy; официальная сборка завершилась кодом 0. После исправления kit сборка повторена, lockfile не изменился. Прямой clone из GitHub по инструкции в этой сети остаётся неподтверждённым.

Чистая установка обнаружила отсутствующий `kit/source-version.json`: Freeze остановился до изменения ACL. Добавлен текстовый манифест трёх файлов зависимостей; проверка выполняется до обхода дерева, допускает эквивалентные LF/CRLF и отклоняет изменённое содержимое. Шесть регрессионных проверок прошли на хосте и в новой Windows.

Основные 6/6 сценариев выполнены с 4 vCPU, 6 ГБ RAM и динамическим диском 100 ГБ. После холодной загрузки VM с паравиртуализацией minimal зависла; успешный пользовательский запуск выполнен после перехода на 2 vCPU, Hyper-V paravirtualization и host I/O cache. Host Hyper-V/NEM не отключался. Это ограничение проверенной среды VirtualBox, а не доказательство причины зависания. Guest Additions не устанавливались.

На этапе runtime внешние IPv4/IPv6 подключения блокировались Windows Firewall; оставлены loopback, управление через NAT хоста и локальный DHCP. Положительный TCP-контроль работал до блокировки и не работал после неё. Это не полный аудит native/UDP/всех дочерних процессов. Первые пять сценариев используют детерминированный локальный model API; шестой и холодный запуск — настоящую Ollama. Web проверен по HTTP API, а не прохождением каждого экрана браузера. Управление тестами выполнялось через WinRM; ручной интерактивный вход пользователя не является частью нового прогона.

## Подготовка исходного комплекта на хосте

Эта версия меняет состав поставки: исходники вместо встроенных программ, модели и runtime. Продуктовые исходники packages/apps/native/vendor/python сохранены; изменение токеноподобного синтетического fixture было выполнено ранее. Установка зависимостей по неизменённому lockfile из отдельного локального кэша и официальная сборка прошли. Сборка заняла 492,203 секунды и сформировала 348 клиентских артефактов вне Git. Синтаксис 9 PS-скриптов, 8 примеров PowerShell и 7 JS-драйверов проверен; CLI/SDK пути сборки найдены, SDK импортирован. Обезличенный итог находится в [evidence/source-release.json](evidence/source-release.json).

## Предыдущая проверка тех же продуктовых исходников

В отдельной Windows 11 Pro x64 build 26300.9457 (2 vCPU, 6 ГБ RAM, 80 ГБ, NIC отключены) прежний собранный комплект прошёл 6/6 сценариев: SDK write/read/glob/grep, headless, ACP, foreground spawn/fork, Web token/cookie и resume, реальная Ollama Qwen3:0.6b с файлом и событиями write/read. Прошли 13 ACL-canary проверок и настройка английской/русской раскладок. Подробный обезличенный [исторический отчёт](evidence/previous-runtime-test-results.json).

Этот исторический запуск использовал прежний собранный комплект. Проверка новой установки из исходников приведена выше; её результаты не подменяются старым прогоном.

Ранее официальный build, SDK 77, Python 32, admission/fs 42+1 SKIP, локальные permissions/instructions/skills 4 и TCP guard 2 прошли сфокусированные проверки. Широкий исходный suite имел 173 PASS / 47 FAIL / 1 SKIP; полный suite не заявляется пройденным.

## Что остаётся

Проверить прямое скачивание с GitHub в доступной сети, автономную службу/Task Scheduler, background follow-up, продолжительные рабочие задачи и полный native/UDP/child-process аудит. Межпроцессный SDK resume требует отдельной интеграции; Web resume проверен. UI браузера не проверен прохождением каждого экрана. Shell/terminal/PTC/workflow/внешний MCP/общий web fetch остаются выключены. Полный upstream suite и известные четыре отказа SDK не объявляются исправленными.
